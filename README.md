# 🗂️ Всі проекти (Holost)

Локальна система, яка збирає всі ваші проекти з кодом в одному місці. Для кожного проекту є набір кнопок-вкладок: папки, опис, код з редактором, структура БД, API, помилки, тести, git та інше.

Працює на вашому комп'ютері (Flask + SQLite) і нікуди не відправляє дані.

## Запуск

```bash
python -m venv venv
source venv/bin/activate          # Windows: venv\Scripts\activate
pip install -r requirements.txt
python run.py --open              # http://127.0.0.1:5000
```

Далі натисніть **⚙️ Папки з проектами**, вкажіть, де лежать ваші проекти (наприклад, `~/projects`, `~/PycharmProjects`), і натисніть **🔄 Сканувати папки**. Окремий проект можна додати кнопкою **➕ Додати проект**.

## Що є (за планом)

| План | Де в застосунку |

| 1) Локальна система | Flask-сервер на `127.0.0.1`, дані в `instance/holost.db` |
| 2) Список всіх проектів з кодом | Головна: картки проектів зі стеком, git-гілкою, незакоміченими змінами, помилками; пошук і фільтр за технологією; сканер папок; ⭐ обрані |
| 3) Кнопки по кожному проекту: | Сторінка проекту → вкладки |
| — Папки, де все лежить | **📁 Папки**: навігація по папках, відкрити в провіднику, копіювати шлях, створити/перейменувати/видалити |
| — Короткий та повний опис | **📝 Опис**: короткий опис, теги, повний опис у Markdown з переглядом, README проекту |
| — Код з редактором | **💻 Код**: дерево файлів + редактор з підсвічуванням (CodeMirror), `Ctrl+S`, захист від перезапису змін на диску |
| — Структура БД | **🗄️ Структура БД**: SQLite-бази (таблиці, колонки, зв'язки, індекси, к-сть рядків, SQL-консоль лише для читання), схеми з `*.sql`, ORM-моделі SQLAlchemy / Django / SQLModel, папки міграцій |
| — Структура використання | **🧭 Використання**: команди встановлення/запуску/тестів, точки входу, скрипти (npm, Makefile, Procfile), залежності, змінні оточення (тільки назви), конфіги, CI, Docker-сервіси + ваші нотатки |
| — Можливість вносити зміни через застосунок | Редагування коду, файлів, опису, налаштувань, коміти — усе з інтерфейсу; кожна зміна потрапляє в історію |
| — Писати API, пошук та ін. | **🔌 API**: знайдені в коді ендпоінти (Flask, FastAPI, Django, Express, Go, Spring), клієнт для запитів, збережені запити з нотатками. **🔍 Пошук**: по всьому коду, регістр, регулярні вирази, маски файлів |
| — Візуал, картинки | **🖼️ Візуал**: галерея всіх картинок проекту, перегляд, завантаження нових (скріни, макети, схеми) |
| — Оновлювати з проду | **⬇️ Оновлення з проду**: `git fetch` + `git pull --ff-only` з обраного remote/гілки або своя команда (`rsync`, `scp`, `ssh …`), журнал запусків |
| — Історія змін | **🕘 Історія змін**: зміни через застосунок з диффами + git-коміти (у т.ч. історія окремого файлу) |
| — Падіння, помилки | **💥 Падіння, помилки**: інциденти (вручну, з логів, або проект сам надсилає їх через HTTP), групування однакових помилок, статус «вирішено»; перегляд лог-файлів з підсвічуванням помилок і трейсбеків |
| — Структура проекту | **🌳 Структура проекту**: статистика (файли, рядки, мови), дерево, найбільші файли, ключові файли |
| — Тести + Git | **✅ Тести + Git**: запуск тестів (команда визначається автоматично: pytest, npm test, go test, cargo test…), історія запусків; git-статус, дифф, коміт, гілки, pull/push/fetch, `git init` |

## Як проект може сам надсилати свої падіння

У вкладці **💥 Падіння, помилки** → «Як проект може сам надсилати помилки сюди» є готовий код для Python і curl з персональним ключем проекту. Коротко:

```bash
curl -X POST http://127.0.0.1:5000/api/ingest/<ключ> \
  -H "Content-Type: application/json" \
  -d '{"title": "Щось впало", "traceback": "...", "level": "error"}'
```

## Налаштування

| Змінна | Що робить |
|---|---|
| `HOLOST_ROOTS` | Папки з проектами за замовчуванням (через `:`, на Windows через `;`) |
| `HOLOST_DATA_DIR` | Де зберігати базу Holost (`./instance`) |
| `HOLOST_COMMAND_TIMEOUT` | Ліміт часу для тестів та оновлення з проду, секунд (600) |
| `HOLOST_ALLOWED_HOSTS` | Дозволені хости через кому (`127.0.0.1,localhost,::1`) |

`python run.py --port 8080` — інший порт.

## Безпека

Застосунок вміє запускати команди й змінювати файли, тому:

- за замовчуванням слухає лише `127.0.0.1` (не відкривайте його в мережу);
- усі змінюючі запити вимагають CSRF-токен, а запити з чужих хостів відхиляються (захист від DNS-rebinding);
- доступ до файлів обмежений папкою проекту;
- SQL-консоль відкриває базу лише для читання;
- значення змінних з `.env` не показуються, лише їхні назви.

## Розробка

```bash
pip install -r requirements-dev.txt
python -m pytest
```

Структура:

```
run.py                  точка запуску
holost/
  __init__.py           create_app()
  db.py                 SQLite-сховище Holost
  security.py           CSRF, перевірка хоста
  routes/pages.py       HTML-сторінки
  routes/api.py         JSON API
  services/             логіка: fs, git_ops, scanner, dbschema, apiscan, usage, search, logs, runner, httpclient
  templates/            Jinja-шаблони
  static/               CSS, JS, CodeMirror (vendor)
tests/                  pytest
```

Редактор коду — [CodeMirror 5](https://codemirror.net/5/) (MIT), лежить у `holost/static/vendor/codemirror`, тож усе працює без інтернету.
